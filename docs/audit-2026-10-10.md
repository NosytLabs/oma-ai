# Platform audit — October 10, 2026

This audit covers the Vercel frontend, Neon API configuration, model catalog, public pages, local authenticated user/admin flows, and payment implementation. It does not establish that every upstream model or every mainnet funding rail is healthy. Canonical behavior and operator configuration live in [PLATFORM.md](PLATFORM.md); deployment targets live in [DEPLOYMENT.md](DEPLOYMENT.md).

## Admin console

The console has an overview with durable request/error and charge/cost charts for 24 hours, 7 days, and 30 days. It separates customer charges, known provider costs, errors, canceled streams, and model fallbacks. UTC buckets include empty periods. Worker HTTP counters are labeled separately because they reset on restart.

Usage logs provide account/request search, outcome/date filters, 25-row pages, and expandable routing details. They show the requested and actual model, attempts, tokens, charge, latency, refund status, and cost availability. Pagination preserves Postgres microseconds; the real database test caught an initial cursor precision problem. Prompts and completions are excluded from the returned metadata.

Spend totals cover the whole selected range even when the grouped list is truncated. Refunded usage and failed deductions do not count as customer charges. Canceled/error completions retain consumed-token estimates without deducting customer credits. GNK procurement cost is not recorded in dollars, so its estimated gross margin is unavailable.

Credit deduction and usage records preserve the database's eight decimal places in cents. The previous four-decimal conversion could round short $0.02/M Gonka requests to zero; a regression check verifies a three-token request retains its nonzero charge in both the usage record and debit.

User controls show lifetime usage, account IDs, balances, and suspension. The current administrator cannot suspend itself. Negative adjustments stop at the existing balance and only book the amount actually removed; audit events retain the requested amount and whether it was capped. Private settings preserve the maintenance message independently of public rail availability.

The local sitemap audit checked 65 public URLs: HTTP 200, canonical URLs, unique titles/descriptions, one H1/main landmark, and indexable structured-data behavior. This is structural SEO validation, not a ranking or Core Web Vitals certification.

## Models, pricing, and requests

Frontend and backend now share `server/src/inference/model-catalog.json`. It contains 20 chat entries: 17 Venice routes and 3 Gonka/OpenBroker routes. Availability excludes the paused DeepSeek route; Venice Mistral was removed. Model pages show context/output limits and long-context rates where applicable.

- Gonka retail: **$0.02 per million input tokens and $0.02 per million output tokens**.
- Venice retail: **50% markup** on catalog upstream rates, including extended-context tiers.
- Gonka USD cost/margin: unknown until settled GNK acquisition and request costs are recorded. A percentage markup cannot be substantiated from an assumed zero cost.

Fixed the chat middleware reading an already-consumed request body, which caused real requests to fail. Preserved nullable assistant content, `tool_calls`, and `tool_call_id` through both request conversions. Regression tests inspect the actual provider payload rather than only a route mock.

Live MiniMax returned a valid function call for adding 17 and 25. Its tool-result continuation exceeded the previous short timeout; after the timeout fix, the same model completed the continuation with `42`, HTTP 200, no fallback, and 184 reported tokens in about 75 seconds. This verifies one live tool flow, not all coding agents or every model. DeepSeek's real probe repeatedly exhausted its output limit without a usable completion; it is paused with an explicit 503 and excluded from fallbacks.

The gateway now uses a **240-second total inference budget**, OpenBroker attempts up to 180 seconds, a 270-second frontend proxy timeout, and a 300-second Vercel route limit. Cancellation reaches the provider and prevents further retries. Response bodies remain bounded after headers arrive. Per-attempt timeouts advance to the next configured model rather than retrying the same slow route. Error logs retain routing/status metadata instead of raw upstream bodies that may echo private content.

[OpenBroker's FAQ](https://openbroker.gonka.gg/docs/faq) describes global concurrency/capacity limits and potentially long host-selection waits. Its [pricing documentation](https://openbroker.gonka.gg/docs/pricing) describes token/attempt charges in GNK. OMA's own RPM/TPM and daily website allowance remain distinct from these upstream limits. Neither public RPC fallbacks nor a longer inference timeout guarantee continuous upstream availability.

## Payments and treasury

The durable Postgres credit ledger is authoritative. One credit equals one US cent. Treasury funds, facilitator gas, and provider procurement balances are separate from a customer's spendable credits.

| Flow | Payment movement | Credit grant |
|---|---|---|
| Card pack | Polar hosted checkout | Signed order webhook |
| Direct USDC | Base transfer to configured deposit recipient | Confirmed transfer evidence |
| x402 | `/x402/verify` broadcasts an EIP-3009 transfer; facilitator pays gas | `/x402/settle` binds evidence to the payer's SIWE session |

**OMA's `/x402/verify` is a transfer operation, not a dry-run verification.** Settlement does not send a second payment. The direct deposit recipient may differ from the x402 recipient; clients must read the correct configuration. Transaction-hash idempotency prevents duplicate crediting and chain recovery supports retry after cache loss. Ordinary chat spends prepaid credits; it does not issue a mid-request payment challenge.

`GET /x402/info` now works through the frontend and exposes Base mainnet configuration without caching. The verified production x402 recipient is `0x3144293aacc1c26eb803591151d775ed89eefcfe`. Configuration alone does not establish the facilitator's gas balance or a successful purchase. No real card purchase, USDC payment, or production account deletion was performed during this audit.

Added free public Base RPC fallbacks to both reads and facilitator broadcasts. Checked chain ID 8453, removed a provider returning HTML, and filtered placeholder/duplicate URLs. Tests force a primary failure and verify backup completion. Public endpoints can rate-limit; QuickNode remains preferable when configured.

## Dependencies and infrastructure

Updated compatible direct npm dependencies and the pnpm lockfile, including Next.js, Better Auth, wallet/web3 libraries, and the Polar SDK. Fixed ignored root overrides by placing them under pnpm configuration. Retained Node 24 types to match production and TypeScript 6 to remain within the installed ESLint parser's supported range.

`pnpm audit --prod` reports **zero vulnerabilities**. The full audit retains one unpatched high-severity `braces` advisory in the Next ESLint/fast-glob development dependency chain. It is not present in the production-only audit; do not represent the entire dependency tree as vulnerability-free.

The usage migration was present but missing from the migration journal. Registered it and verified a fresh database includes all metering columns. Production already had those columns; no production schema change, table drop, or data purge was needed. The inspected production tables were small, with no demonstrated obsolete-table target.

Neon deployment preserves existing environment keys and triggers. Vercel deploys only the frontend from repository root with Root Directory `app`, Node 24, and the existing `oma` project. Obsolete preview cleanup must retain the current production deployment and the last known production rollback. Financial/authentication audit history is retained; provider runtime logs follow platform retention rather than a blanket deletion.
