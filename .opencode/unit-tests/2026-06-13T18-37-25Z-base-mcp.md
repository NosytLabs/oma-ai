## Reviewer's Independent Re-Verification of HIGH-Severity Bugs

### Bug #1: Wrong Solana USDC mint in `server/src/routes/jupiter.ts:19`

Reviewer read the file directly. Line 19:
```ts
export const USDC_MINT = "EPjFWdd5AufqSSqeM2qN1xzybapC8DM4GMX5HEsPsS1";
```

Reviewer grepped for all `USDC_MINT` usages:
```
19:  export const USDC_MINT = "EPjFWdd5AufqSSqeM2qN1xzybapC8DM4GMX5HEsPsS1";
260:        if (info.destination === treasuryAddress && info.mint === USDC_MINT) {
473:      outputMint: USDC_MINT,
482:      outputMint: USDC_MINT,
```

✓ **CONFIRMED.** The wrong mint is used in 4 places: the constant definition, the deposit verification check, and 2 Jupiter swap outputMint assignments. The canonical Circle USDC mint on Solana is `EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v` (last 22 chars differ: `C8DM4GMX5HEsPsS1` vs `C8G4wEGGkZwyTDt1v`).

**Impact:** Every USDC-on-Solana deposit verification via the Jupiter route will silently fail (the `info.mint === USDC_MINT` check never matches real USDC deposits). Every Jupiter quote/swap is pinned to the wrong output mint.

**Severity:** HIGH. Real money path, broken, silent failure.

### Bug #2: Typo in `docs/API-DOCUMENTATION.md:414`

Reviewer grep'd the docs file. Line 414:
```json
"asset": "0x833589fCD6eDb6E08f4c7C32D4f71b54cA3B8766",
```

✓ **CONFIRMED.** Last 5 hex chars are `3B8766` instead of `bdA02913`. EIP-55 checksum is mixed-case and depends on the keccak256 of the lowercase hex — a single-character mutation breaks it. The MCP `get_token_info` tool rejected this string with `INVALID_ARGUMENT` (bad checksum).

**Impact:** Any client that copies the `pay_req.asset` field verbatim will get `INVALID_ARGUMENT` from ethers/viem at the wallet-signature step. Customer-facing documentation bug.

**Severity:** HIGH. Breaking, customer-facing.
