# Linking Audit — OMA-AI

**Date:** 2026-07-02
**Scope:** All public-facing and authenticated pages under `app/src/app/`
**Method:** Read-only code grep + curl verification against the dev server (port 3000)
**Verdict:** All routes resolve (200 public / 307 auth-gated). Two real link-fidelity defects and one cosmetic dead anchor. Several copy/CTA inconsistencies to clean up.

---

| Severity | Count | Examples |
|---|---|---|
| **P0** | 2 | `/dashboard?tab=…` links don't open the targeted tab · `/dashboard?demo=1` is a no-op |

## P0 — broken: user can't complete the intended flow

### P0-1 — `/dashboard?tab=health` and `/dashboard?tab=api-keys` are ignored

The `DashboardHeader` renders `<Link href="/dashboard?tab=health">` (line 333) and the `ApiKeysSection` renders `<Link href="/dashboard?tab=api-keys">` (line 162). The dashboard page never reads `?tab=` from the URL — `useState<TabId>("overview")` always starts on the Overview tab and tab changes update only local state, not the URL.

- **Expected:** Click "API keys" link from `/settings` → land on `/dashboard` with the API Keys tab active.
- **Actual:** Lands on `/dashboard` Overview. The user has to click the tab a second time.
- **Source → broken target → expected vs actual:**
  - `app/src/components/dashboard/OnboardingChecklist.tsx:106` (via QuickActions) — uses `https://docs.oma.ai` (see P1-2), but the on-page tab navigation is `setActiveTab` only.
  - `app/src/app/settings/_components/ApiKeysSection.tsx:162` — `<a href="/dashboard?tab=api-keys">` → opens Overview, not api-keys.
  - `app/src/app/dashboard/_components/DashboardHeader.tsx:333` — `<Link href="/dashboard?tab=health">` → opens Overview, not health.
- **Fix:** Read `useSearchParams().get("tab")` in `dashboard/page.tsx` and seed `activeTab` from it; also push `setSearchParams` when the user clicks a tab so the URL stays in sync.

### P0-2 — `/dashboard?demo=1` does nothing

`settings/page.tsx:292` has `<a href="/dashboard?demo=1">Try the dashboard in demo mode</a>`. There is no demo mode in the codebase (the `?demo=1` parameter is not read anywhere). The link is a non-functional CTA.

- **Expected:** A demo view of the dashboard (sandbox data, no real API calls).
- **Actual:** Loads the regular dashboard, which is empty for an unauthenticated user. The text implies a feature that doesn't exist.
- **Source:** `app/src/app/settings/page.tsx:292`.
- **Fix:** Either implement a demo data mode that activates on `?demo=1`, or remove the link.

## P1 — works, but copy/destination is inconsistent

### P1-1 — "Get API Key" lands on `/login`; "Get your API key" lands on `/chat`

Two CTAs on the same homepage with the same intent but different destinations.

| Source | Copy | href | Where it actually goes |
|---|---|---|---|
| `app/src/app/_components/home/hero.tsx:99` | **Get API Key** | `/login` | Auth flow, then bounce to `?next=/dashboard` |
| `app/src/app/_components/home/final-cta.tsx:46` | **Get your API key** | `/chat` | Auth-protected playground; unauthed user hits 307 → `/login?next=/chat` |

- **Behavior:** Both eventually end up on `/login`, but the path is different and the label says different things.
- **Why it matters:** A user clicking "Get API Key" twice on the same page may get two different intermediate pages, which feels broken.
- **Fix:** Point both at `/login` (since both ultimately require auth), or unify the copy.

### P1-2 — Three hardcoded `https://docs.oma.ai` links to an external domain when `/docs` is the local equivalent

`/docs` is a full, working local route (200, all 10 sections present). But three dashboard components link to the external `https://docs.oma.ai` domain instead. This sends logged-in users to a different site for documentation when a local one exists.

- `app/src/app/dashboard/_components/QuickActions.tsx:42` — `{ href: "https://docs.oma.ai", label: "Read the docs" }` (QuickActions card on dashboard)
- `app/src/components/dashboard/OnboardingChecklist.tsx:106` — `<Link href="https://docs.oma.ai">Read the docs</Link>` (onboarding checklist)
- `app/src/app/dashboard/_components/DashboardGrid.tsx:377` — `<a href="https://docs.oma.ai">Read the docs →</a>` (empty state when no usage data)

- **Fix:** Replace with `href="/docs"` everywhere. The `external: true` flag and `target="_blank"` should be removed.

### P1-3 — `/chat?model=…` from model detail is not the playground route

Model detail pages (`app/src/app/models/[slug]/page.tsx:211, 302`) have "Use in Playground →" links that go to `/chat?model=…`. But the app has a separate `/playground` page (`app/src/app/playground/page.tsx`).

- **Expected:** The label "Use in Playground" suggests the user will land on `/playground`.
- **Actual:** They land on `/chat`, which is a different page (chat shows messages by default; playground is a request/response shell).
- **Fix:** Either rename the CTA to "Open in chat" or point it to `/playground?model=…` if playground reads that param (it doesn't currently — see the `[x]` note below).

> **Note:** `/playground/page.tsx` is gated by auth (307 → `/login` when unauthed) and currently does not read the `?model=` param. The chat page reads it. This is a separate flow-design issue, not a broken link.

### P1-4 — Settings link to `/settings` from inside `/settings` itself is a no-op

`app/src/app/login/page.tsx:832` has `<Link href="/settings">settings</Link>`. The wording is "switch methods anytime from settings" — which is correct intent, but a user who just signed in is already *on* the settings-equivalent path or is going to land on `/dashboard` first (via `next=` redirect). The link works (307 → `/login?next=/settings` for unauthed, but post-auth lands on settings). No bug; flag for review.

## P2 — cosmetic

### P2-1 — Dead `#subject` anchor in legal pages (hidden TOCs)

All three legal pages (terms, privacy, disclosures) have a hidden screen-reader-only TOC at the bottom with `<a href="#subject">Summary</a>`. None of those pages has an element with `id="subject"` — the summary is the first card in the hero and has no anchor.

- **Pages affected:**
  - `app/src/app/terms/page.tsx:560` (`<a href="#subject">Summary</a>`)
  - `app/src/app/privacy/page.tsx:625` (`<a href="#subject">Summary</a>`)
  - `app/src/app/disclosures/page.tsx:399` (`<a href="#subject">Summary</a>`)
- **Why it matters:** Hidden TOCs are surfaced to screen readers and search engines. The link target doesn't exist; crawlers see a broken anchor.
- **Fix:** Either add `id="subject"` to the summary card in each page, or remove the Summary link from the hidden TOC.

### P2-2 — Plain `<a>` instead of `<Link>` for `/docs#x402` in login X402Callout

`app/src/app/login/page.tsx:390–396` renders:

```tsx
<a href="/docs#x402" className="…">
  How x402 works
  <ArrowRight … />
</a>
```

The same component file uses `<Link href="/docs">` and `<Link href="/docs#x402">` on lines 467–479. The plain `<a>` triggers a full page reload instead of client-side navigation, which is inconsistent with the rest of the login page and slower.

- **Fix:** Replace with `<Link href="/docs#x402">`.

### P2-3 — "Related post" flow does not exist (task asked us to check)

The audit brief asked: *"Blog post → related post → verify exists."*

Looking at `app/src/app/blog/[slug]/page.tsx` and `app/src/lib/blog-data.ts`, blog posts have **no "related post" feature**. Each post has a "All posts" link back to `/blog`, but no inter-post navigation. If a related-posts feature is intended, it is missing. If not, the brief's flow is vacuously satisfied (no broken link because the link doesn't exist).

- **Recommendation:** Either add a "Related posts" component (the model-detail page has a good `RelatedModels` pattern to copy), or accept that this is an intentional omission and remove the line from the audit brief.

### P2-4 — `mailto:` addresses and `api.oma-ai.com` references are hardcoded

Not strictly a broken-link issue, but flagged for completeness:

- All `mailto:` links use `support@oma-ai.com`, `legal@oma-ai.com`, `billing@oma-ai.com`, `privacy@oma-ai.com`, `hello@oma-ai.com`. These are not internal links, but they are copy strings that should live in one config file (not eight).
- `https://api.oma-ai.com/v1` is hardcoded in `app/src/app/_components/home/hero.tsx:19`, `app/src/app/_components/home/code-example.tsx:19`, `app/src/app/playground/page.tsx:23`, and the `DEFAULT_API_URL` constant in `app/src/lib/config.ts`. This is a documentation/production-config concern, not a routing one — the API URL is the destination of an HTTP call, not a clickable link.
