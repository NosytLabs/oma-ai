## 2. Visual issues found

### P0 — Layout breaks, missing content, broken CTAs

#### 2.1 `/login` — page is a permanent skeleton on both viewports
**Severity:** P0 — page is non-functional on every entry path.

The `/login` route renders `<div class="h-10 w-full animate-pulse rounded-lg bg-surface"></div>` (and 3 sub-bars) with `aria-busy="true"` and a screen-reader label `Preparing wallet session…`. Captured DOM at `+5s` after `wait_for_load`: no `<input>`, no sign-in button, no OAuth provider. The loading state never resolves because the page is gated on the wallet/Privy hydration that, in this headless environment, never completes.

Evidence: `app/src/app/login/page.tsx` (the `aria-busy` skeleton) + `login-desktop.png`, `login-mobile.png` (both show only 3 grey bars and a 1166/1619 px page that is mostly empty).

**Fix path:** add a non-wallet fallback (email/SIWE direct link) or render a static "Connect wallet to continue" panel after a hydration timeout so the page is never blank.

#### 2.2 `/` home — 4 React `Invalid prop 'className' on React.Fragment` errors
**Severity:** P0 — code defect; the page hydrates with warnings on every load (4× desktop, 4× mobile). Even though the page eventually renders, this is a real component bug.

Evidence: `_results.json` → `console_errors[].text` (4 entries on home/desktop and home/mobile).

**Fix path:** grep source for `<Fragment` or `<>` with `className=` and replace with `<div>` (or move the className onto a real element).

#### 2.3 `/blog` — posts displayed out of chronological order
**Severity:** P0 — visible at first glance on both viewports.

The four posts render in the order **Jun 14 → Jun 19 → Jun 24 → Jun 21**. The 4th post (Jun 21) is dated *before* the 3rd (Jun 24) but rendered after. The data array `BLOG_POSTS` in `app/src/lib/blog-data.ts` is declared in the order 06-15, 06-20, 06-25, 06-22 and the page renders it in declaration order.

Evidence: `app/src/lib/blog-data.ts` lines 36–72 (the `publishedAt` field is the sort key, but no `.sort()` is applied before `.map()` in `app/src/app/blog/page.tsx` line 53).

**Fix path:** add `.sort((a, b) => b.publishedAt.localeCompare(a.publishedAt))` (or use `Date.parse`) before the grid map. For a future-proof design, render the date as a sortable key on the data object and sort at module load.

#### 2.4 `/about` — hard-coded "Last commit 2026-06-12" displayed to users
**Severity:** P0 — actively misleading the public.

The about page renders a literal "Last commit 2026-06-12" in the "At a glance" sidebar. Today is 2026-07-02; the value is 3 weeks stale and was apparently never wired to `git log` — it is a `const ISSUED = "2026-06-12"` at line 87 of `app/src/app/about/page.tsx`, rendered as `Last updated · {ISSUED}` at line 257.

Evidence: `about-desktop.png` and `about-mobile.png` both show "Last commit 2026-06-12" in the right column.

**Fix path:** replace the const with a derived value from `git log -1 --format=%cd` (build time) or read from an env var. If intentional, at least refresh the hard-coded value.

#### 2.5 `/image-generation` and `/video-generation` mobile — H1 cut off by sticky nav
**Severity:** P0 — the most important text on the page is hidden under the nav.

On both pages, the H1 ("Image Generation" / "Video Generation") is positioned *behind* the sticky mobile nav when the page is at scroll-top, because the page content's `pt-*` (top padding) is not large enough to clear the 45 px nav. The full-page screenshot captures the moment: the top of the H1 is visibly cropped by the navbar bar. (Reproducible in viewport-only capture too.)

Evidence: `image-generation-mobile.png` shows "Ima__ Gen…" (the centre of "Image Generation" is hidden behind the nav bar at the top of the scroll-stitched image, the same artifact is visible on the 2nd stitch). `video-generation-mobile.png` shows the same effect for "Video Generation".

**Fix path:** bump mobile top padding on the `/image-generation` and `/video-generation` route content wrappers from `pt-12 sm:pt-20` to `pt-20` (or add a `pt-14` shell wrapper) so the H1 clears the sticky nav on initial render.

#### 2.6 `/` home mobile — trust strip overflows
**Severity:** P0 — content is clipped on the most visible marketing page.

The "Routing through" strip ("OpenAI · Anthropic · Venice · Llama · DeepSeek · Genmo") overflows the 390 px viewport and "DeepSeek" is rendered as "DeepS" (truncated). Confirmed on `home-mobile.png`. Desktop is fine (overflow allowed because of whitespace).

Evidence: `home-mobile.png` shows "OpenAI · Anthropic · Venice · Llama · DeepS" with the rest cut off. Desktop renders the full string in the available space.

**Fix path:** either (a) reduce the gap between provider names on small viewports, (b) marquee/auto-scroll, (c) hide the strip below `sm` and show a single "Powered by 6 providers" line, or (d) wrap to two lines intentionally with `flex-wrap` and a smaller font.

### P1 — Alignment, awkward wraps, inconsistent spacing

#### 2.7 `/swap` — "x402 PER-REQUEST" badge text wraps to 3-4 lines
**Severity:** P1 — the small floating pill at the top of the page reads "X402 / PER- / REQUEST / →" (line-broken on every breakable character). The pill is clearly width-locked but its contents were authored as a single line. Visible on both desktop and mobile.

Evidence: `swap-desktop.png` (top-centre), `swap-mobile.png` (top-centre).

**Fix path:** increase the pill's `min-w` to fit "x402 PER-REQUEST" on one line, or replace the contents with a single word ("x402") and the descriptor as a separate tooltip.

#### 2.8 `/video-generation` desktop — subtitle wraps with dangling "from $0.90."
**Severity:** P1 — visible awkward line break.

The hero description reads "Generate videos from text prompts. Powered by Seedance 2.0 and Kling V3 Pro. Priced per generation — from $0.90." The em-dash + "from $0.90." is on its own line, separated from the preceding "generation —" by a line break. This is a content/layout interaction issue.

Evidence: `video-generation-desktop.png` line 4 of the hero text.

**Fix path:** wrap "from $0.90." in a `<span class="whitespace-nowrap">` so the price + currency never splits, or rephrase to "from $0.90 per generation."

#### 2.9 `/docs` mobile — code blocks truncate instead of horizontal-scroll
**Severity:** P1 — the most common "code-on-mobile" anti-pattern.

The `Your First Request` cURL block on mobile shows the URL truncated as `v1/c...om` and the API key as `oma_s_...UR`. The block does not have `overflow-x: auto` (or has it but the inner text is being clipped, not scrolled). On desktop the same block fits comfortably.

Evidence: `docs-mobile.png` (Quick Start section, second code block).

**Fix path:** wrap the `<pre>` inner content in a horizontally-scrollable container with `overflow-x: auto` + `white-space: pre`, or apply `break-all` selectively on long URLs.

#### 2.10 `/` home mobile — hero code preview overflows
**Severity:** P1 — same root cause as 2.9 on the home hero.

The hero code block (the request example) shows `curl https://api.oma-ai.com/v1/chat/completio` (cut off). The block does not have a horizontal scroll on mobile; content is clipped at the right edge.

Evidence: `home-mobile.png` (hero code preview tile, second-to-last visible line).

#### 2.11 `/models` mobile — card body text overflows the card
**Severity:** P1 — visually broken.

The "Gemini 2.5 Flash" card on mobile shows the model ID as `…mi-2.5-flash` (cut off at the left). The card has `overflow: hidden` but the inner text uses an element that doesn't fit at 390 px.

Evidence: `models-mobile.png` (Gemini 2.5 Flash card, mid-page).

**Fix path:** add `min-w-0` to the inner flex container and `truncate` or `text-ellipsis` to the ID, or remove the icon prefix at small viewports.

#### 2.12 `/pricing` mobile — tier filter pills wrap with orphan "Budget"
**Severity:** P1 — last pill is alone on its own line.

Filter row on pricing-mobile: `All · Frontier · Premium · Mid-Range` (row 1) and `Budget` (row 2, alone). Looks like 5 pills in 2 rows. Acceptable but the orphan is visually unbalanced.

Evidence: `pricing-mobile.png` (just above the model table).

**Fix path:** reduce pill padding on small viewports, or wrap intentionally with `flex-wrap` and equal-width pills, or hide the label and use icons below `sm`.

#### 2.13 Sentry double-init warning
**Severity:** P1 — every page emits `[@sentry/nextjs] You are calling Sentry.init() more than once on the client. This can happen if you have both a sentry.client.config.ts and a instrumentation-client.ts file with Sentry.init() calls. It is recommended to call Sentry.init() once in instrumentation-client.ts.`

Evidence: `_results.json` (warning present in all 24 captures).

**Fix path:** remove `Sentry.init()` from `app/sentry.client.config.ts` and let `app/instrumentation-client.ts` be the single init point (Sentry's own recommendation).

#### 2.14 Models desktop — last grid row has a single orphan card
**Severity:** P1 — 13 cards in a 4-column grid leaves 12+1 with the 4th slot empty.

`/models` renders 13 model cards in a `sm:grid-cols-2 lg:grid-cols-3` (or 4?) grid. The last row has only the 13th card and three blank columns. Visible in `models-desktop.png`.

**Fix path:** change the layout to `lg:grid-cols-3` (9 + 4, still leaves 1), or add a 14th "Coming soon" card to round out the grid, or change to a 2-column grid for the 13th.

#### 2.15 Login CSRF pre-fetch 429
**Severity:** P1 — the login page is being rate-limited by the server before it can render. This is a symptom of the broken login (2.1) but also indicates the server is denying CSRF token issuance.

Evidence: `_results.json` → `login/console_warnings` includes `CSRF pre-fetch failed: ApiError: [429]`.

### P2 — Polish, microcopy, tone

#### 2.16 Sentry DSN not set
`Sentry Logger [warn]: No DSN provided, client will not send events.` appears on every page. If Sentry is in use, set the DSN. If it is unused, drop the calls.

#### 2.17 WalletConnect project ID is placeholder
`[wagmi] NEXT_PUBLIC_WALLETCONNECT_PROJECT_ID is set to the default placeholder. WalletConnect connector will not be registered.` — replace with a real project ID from cloud.walletconnect.com or accept that WalletConnect is intentionally disabled in dev.

#### 2.18 Next.js dev tools "N" indicator visible in screenshots
A small circle with "N" appears on the left side of every page (`*.desktop.png` and `*.mobile.png`). This is the Next.js dev tools indicator, only present in dev mode. Cosmetic, not a defect — but if these screenshots are circulated as design references, the indicator should be suppressed.

#### 2.19 Sticky-nav re-capture artifact in full-page screenshots
`capture_screenshot(full=True)` does scroll-and-stitch, which causes the sticky `<header>` to be re-rendered at every scroll position. The result is a "nav repeated down the page" effect in every full-page screenshot. This is **a screenshot-tool artifact, not a real visual bug**, but if anyone in the team uses the screenshots for review they will be confused. Documenting here so the next reviewer doesn't file a P0.

#### 2.20 Footer "N" overlaps with logo
On some mobile pages (faq-mobile, image-generation-mobile, video-generation-mobile, status-mobile) the Next.js "N" indicator overlaps the footer's "oma" logo, the page heading, or the supported-wallets checkmarks. Cosmetic, dev-only.

#### 2.21 About page "Last commit" wording inconsistency
"Last commit" is labelled with the same field as `Last updated` (line 257 of `app/src/app/about/page.tsx`). The label says "commit" but the value is `ISSUED` (publication date). Either the field name or the displayed label is wrong.

#### 2.22 Home page — large dark gaps between sections
On `home-mobile.png` there is approximately 200-300 px of empty dark space between (a) the hero CTA + code preview and the trust strip, and (b) the trust strip and the capabilities section. On desktop the gaps are smaller but still visible. This may be intentional (decorative breathing room) but the magnitude is large enough to make the page feel unfinished.

#### 2.23 Section dividers on `home-desktop` and `pricing-desktop`
Faint horizontal lines (border-y border-border-subtle) appear between sections. They are visible as `~0.1 opacity` lines on otherwise-empty dark space. Fine on desktop, slightly noisier on mobile.

## 5. Recommended fix order (highest ROI first)

1. **Login page (2.1)** — gate a wallet-free fallback (email, "use without sign-in" link) so the page is never blank. One-day fix; unblocks everyone who lands on `/login` from a marketing CTA.
2. **React.Fragment `className` (2.2)** — find the offending element (likely in a shared nav or section component) and replace `<>` with `<div>` or move the className. 30-min fix.
3. **Blog sort (2.3)** — add a sort in `blog-data.ts` or the page map. 5-min fix.
4. **Stale "Last commit" (2.4)** — replace the const with build-time `git log` or env. 30-min fix.
5. **Mobile H1 clipping (2.5)** + **trust strip overflow (2.6)** — adjust `pt-*` on image/video-gen; flex-wrap or marquee on home trust strip. 1-2 hour combined.
6. **Sentry double-init (2.13)** — remove one of the two init calls. 5-min fix.
7. **`x402 PER-REQUEST` badge (2.7)** — widen the pill or shorten the label. 30-min fix.
8. **Code blocks on mobile (2.9, 2.10)** — add `overflow-x: auto` to `<pre>` wrappers in the docs + home hero. 1 hour.
9. **Models card overflow (2.11)** — `min-w-0` + `truncate` on the model ID element. 15-min fix.
10. Everything else is polish and can wait.
